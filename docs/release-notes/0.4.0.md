# Release 0.4.0 - swe-router routes on a rubric, and a second repository

**October 2026**

Version bump: **MINOR** -- adds a second dataset (21 tasks from cli/cli, the GitHub CLI, in Go) with the three Claude 5.5 models run on it, and moves the `swe-router` skill to 0.2.0, which picks a model from a six-question task rubric. Every published benchmark score and cost from 0.3.0 stands unchanged.

---

## Upgrading from 0.3.0

This repo is cloned and run, not deployed, so upgrading is a pull plus a dependency sync.

```bash
git pull origin main
git checkout 0.4.0

cd benchmarks && uv sync && cd ..
cd self-hosted/vllm && uv sync && cd ../..
```

Anyone who installed `swe-router` should re-run its installer. The new `route.py` reads only the new `models.json`, so the seven files must come from the same release, which the installer guarantees:

```bash
curl -sL https://raw.githubusercontent.com/aarora79/agentic-coding-harness-benchmarks/0.4.0/vend/swe-router/install.sh | bash -s -- --ref 0.4.0
```

An edited `allowed-models.txt` is kept. The installer now needs `python3` 3.8 or later on PATH, and stops before downloading anything without it.

### Methodology changes

None. Numbers remain comparable with 0.3.0. No frontier JSON under [docs/metrics/](../metrics/) changed in this window, and the cli/cli runs live in their own output scope (`cli-cli-v1`), outside every v2 table and chart.

The router's way of choosing a model changed, which is a change to a skill, not to how a benchmark number is produced. See [New functionality](#new-functionality).

## New functionality

### swe-router 0.2.0: routing on a six-question rubric

The skill used to ask the developer's model for a quality floor and one of four tiers in its own words. It now answers the six questions in [rubric.md](../../vend/swe-router/rubric.md) about the task, 0 to 2 each, and `route.py` does the arithmetic. Four answers add up to the task's **bucket**, its difficulty level (easy, moderate, hard, very hard). `blast_radius` and `verification` set the **required quality**. `route.py` then takes the cheapest permitted model whose mean benchmark score on tasks in that bucket clears it, skips any model that failed a benchmark task in that bucket, and keeps the developer on their model when the rubric answers carry low confidence. `--tier` and `--floor` still work for one release.

Each benchmark task's bucket comes from a rubric pass by Claude Opus 5.5, three repeats per task, stored in [docs/metrics/swe-router-rubric-mcp-gateway-registry-v2-claude-opus-5-5.json](../metrics/swe-router-rubric-mcp-gateway-registry-v2-claude-opus-5-5.json). The skill never reads that file; `build_vended_models.py` turns it into the per-bucket columns in `models.json`.

Replayed over the 21 v2 tasks, each routed from columns that leave that task out, against `claude-opus-5` on every task:

| Router | Cost saved | Quality change | Tasks below the required quality |
|---|---:|---:|---:|
| swe-router 0.1 | 70.5% | -5.06 | 9 |
| swe-router 0.2.0 | 74.7% | -3.22 | 4 |

Sources: `today-all.json` and `opus-5-5-absolute-all-completion.json` in [docs/metrics/swe-router-rubric-replays/](../metrics/swe-router-rubric-replays/). On cli/cli, columns built from v2 alone routed the Go tasks with no adjustment and erred towards the stronger model.

How it works, with diagrams: [docs/swe-router-how-it-works.md](../swe-router-how-it-works.md). The rubric scores file: [docs/swe-router-rubric-scores.md](../swe-router-rubric-scores.md). The design and its phase 0 test: [docs/swe-router-rubric-design.md](../swe-router-rubric-design.md), [docs/swe-router-rubric-evaluation.md](../swe-router-rubric-evaluation.md).

[PR #223](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/223) (phase 0), [PR #227](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/227) (0.2.0, reviewed as [#226](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/226))

## What's changed

### Skills
- `swe-router` 0.2.0: `rubric.md` and `routing-policy.json` ship with the skill; `SKILL.md` names no measured model, so it no longer goes stale when the data changes; the installer refuses to install without `python3` 3.8+ (#227).
- `run-swe-router-headless.py --mode rubric` scores a dataset's tasks with the rubric and names its output after the dataset and the judge (#223, #225).
- `eval_swe_router.py` gains `--rubric-inputs`, `--columns-from` for zero-shot replays across datasets, and `--min-completion` (#223, #225, #227).

### Documentation and slides
- [docs/results-cli-cli-v1.md](../results-cli-cli-v1.md): the cross-repo answer for #221 (#225).
- The workflow slide, its README image and the ASCII diagram show the rubric flow; both READMEs describe it (#227).
