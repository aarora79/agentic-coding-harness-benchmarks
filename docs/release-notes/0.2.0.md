# Release 0.2.0 - Codex joins the harness list, MiniCPM5-2B joins the frontier

**September 2026**

Version bump: **MINOR** -- adds `codex` as a fifth supported coding harness and MiniCPM5-2B to the omp `/swe3` frontier. Both are additive: no published score or cost from 0.1.0 moved.

---

## Upgrading from 0.1.0

This repo is cloned and run, not deployed, so upgrading is a pull plus a dependency sync.

```bash
git pull origin main
git checkout 0.2.0

# Sync the uv project(s) you run. No dependency changed in this release,
# so a sync is only needed if you are coming from a fresh clone:
cd benchmarks && uv sync && cd ..
cd self-hosted/vllm && uv sync && cd ../..
```

### Methodology changes

None. Numbers remain comparable with 0.1.0. Every entry in the three frontier files was compared between the `0.1.0` tag and this release: [pareto-frontier-omp-swe3.json](../metrics/pareto-frontier-omp-swe3.json) gained `minicpm5-2b`, [pareto-frontier-cc-swe3.json](../metrics/pareto-frontier-cc-swe3.json) and [pareto-frontier-combined-swe3.json](../metrics/pareto-frontier-combined-swe3.json) gained `kimi-k3`, and not one existing model's score or cost per task changed.

The token-accounting fix in [#184](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/184) reads as a methodology change but is not one: it only affects the `codex` agent, which had no published results before this release. The fleet-wide accounting fix that did move numbers shipped in 0.1.0.

## New models

### MiniCPM5-2B on omp / mcp-gateway-registry-v2

A 2.52B dense model scores **42.59** at **$0.3993 per task**, from [pareto-frontier-omp-swe3.json](../metrics/pareto-frontier-omp-swe3.json). It completed **19 of 21** tasks; `derive-repo-url-from-skill-md` and `registration-admission-control-gate` produced no artifacts and are excluded from the mean rather than averaged in as zeros. Per tier it scores 43.76 trivial, 50.96 low, 40.36 medium, 33.45 high ([models.json](../../vend/swe-router/models.json)), so it holds up better on small changes than on architectural ones.

The serving guide is [minicpm5-2b.md](../../self-hosted/vllm/models/minicpm5-2b.md). Two things matter for anyone serving it: the weights are **5.03 GB** in BF16 with a **128K** native context, so it fits one L40S with room to spare, and it needs vLLM's `minicpm5` tool parser because the model emits XML tool calls rather than JSON. The HuggingFace card still points at SGLang for tool calling, which is out of date.

Its throughput sweep ([performance-summary.json](../../self-hosted/vllm/benchmark-output/throughput/minicpm5-2b/performance-summary.json)) ran on `g6e.4xlarge` at $1.298/hr and peaked at **82.49 output tokens/sec at concurrency 7**, with the cheapest blended rate of **$0.04 per 1M tokens** at concurrency 5.

### Qwen3.6-35B-A3B FP8 on a single L40S, held off the frontier

FP8 on one L40S scores **59.23** under omp and **61.45** under codex over the same 21 tasks, against the BF16 four-GPU run's 59.24. Both runs live under [do-not-include/qwen3.6-35b-fp8/](../../benchmarks/swe-benchmark-data/do-not-include/qwen3.6-35b-fp8/) and reach no chart, because the model's only throughput sweep is on `g6e.4xlarge` rather than the canonical `p5en.48xlarge` arm the rest of the fleet is priced on, and its token counts are confounded with a 262144 context window against the BF16 run's 200000. The [do-not-include README](../../benchmarks/swe-benchmark-data/do-not-include/README.md) records both runs, their cost per task on the g6e basis ($0.5555 omp, $0.2645 codex at concurrency 10), and the token-accounting convention each harness uses.

The serving guide is [qwen3.6-35b-a3b-fp8.md](../../self-hosted/vllm/models/qwen3.6-35b-a3b-fp8.md). The useful result: the model runs at its full 256K context on a $1.298/hr single-GPU box at the same quality as its BF16 parent.

## New functionality

### codex as a fifth coding harness

`--agent codex` drives a benchmark run with [OpenAI Codex](../../benchmarks/docs/agent-cli-bedrock-setup.md) (`codex exec --json`). Codex has no `--skill` flag, so the harness inlines the `SKILL.md` into the prompt, the way it already does for kiro-cli. It works on `provider=bedrock` through `AWS_REGION` and the ambient credential chain, and on `provider=endpoint` through `OPENAI_BASE_URL` and `OPENAI_API_KEY`.

Codex reports token counts but no billed cost, so the harness derives cost from a new local price table, [bedrock_pricing.py](../../benchmarks/scripts/bedrock_pricing.py). A model missing from that table yields a null cost rather than a misleading zero.

Its token fields need their own convention. Codex reports `input_tokens` as the full prompt with the cached part as a subset, and the harness subtracts that out before recording, so the fields arrive mutually exclusive. [token_accounting.py](../../benchmarks/scripts/token_accounting.py) therefore declares codex's cache fields disjoint through `DISJOINT_CACHE_AGENTS` instead of detecting the shape from the data. Detection misfires when a codex run's cache hit rate lands near 50%: fresh input then equals `cache_read + cache_write`, the partition branch fires, and the total silently loses the whole cache read, halving the derived cost on the self-hosted path.

[PR #162](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/162) added the agent. [PR #184](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/184) made it runnable end to end and fixed the accounting.

## What's changed

### Documentation

- Root [README](../../README.md) and [harness-reference.md](../../benchmarks/docs/harness-reference.md) now name all five supported harnesses. The agent reference had documented only `claude` and `pi`; it now covers `omp`, `kiro` and `codex`, including each one's cost basis.
- New [b300-cuda-fixes.md](../../.claude/skills/vllm-setup/b300-cuda-fixes.md): the one-time driver and CUDA fixes a B300 node needs before vLLM will serve (#162).
- [agent-cli-bedrock-setup.md](../../benchmarks/docs/agent-cli-bedrock-setup.md) gained the codex-on-Bedrock section: the native `amazon-bedrock` provider needs codex >= 0.144 and no proxy or bearer token (#162).
- New serving guide for [Kimi-K3](../../self-hosted/vllm/models/kimi-k3.md), a 2.8T-parameter MoE with 104B active and native MXFP4 weights (#162).

### Results and frontier

- The Claude Code and combined `/swe3` frontiers now include `kimi-k3` at **73.92** for **$8.81** a task over the 5-task v1 dataset. The run data landed before 0.1.0; this release regenerates the frontier files that had not picked it up (#182).
- Charts, radars, decks and the vended [models.json](../../vend/swe-router/models.json) plus [model-aliases.json](../../vend/swe-router/model-aliases.json) regenerated for MiniCPM5-2B (#182).

## Bug fixes

- The codex agent was unreachable, endpoint runs silently hit Bedrock, and its token totals could drop the cache read. All three are fixed in [#184](https://github.com/aarora79/agentic-coding-harness-benchmarks/pull/184), which closes [#183](https://github.com/aarora79/agentic-coding-harness-benchmarks/issues/183).
- `vend/swe-router/models.json` carried a `source_commit` that no longer existed on `main`, because the file was generated on a branch that GitHub then squash-merged. Restamped, which also unblocked the Test job (#184).
