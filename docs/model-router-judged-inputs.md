# What omp + us.anthropic.claude-opus-5 judges each task to need

The `model-router` skill opens by reading the repository and the task and deciding two things: a **quality floor**, from the consequence of the change being wrong, and a **complexity tier**. Everything the skill does afterwards is arithmetic on those two numbers. It is also the only step with no measurement behind it.

This is that step, run for real: `omp` driving `us.anthropic.claude-opus-5` over every task in `benchmarks/dataset/mcp-gateway-registry-v2.yaml`, each one in its own clone of the target repository at the task's pinned ref, 3 independent time(s) per task. Each run got the skill verbatim and a request for steps 1 and 1b only. None of them selected a model.

- **Repeats.** 3 per task. Floor is the median across them, tier the mode. Where the runs disagreed, every value seen is in the last column.
- **Stability.** The floor was unanimous on 14/21 tasks, the tier on 18/21. Floor disagreed on: cli-custom-egress-oauth-provider-flags, configurable-mcp-proxy-upstream-timeout, configurable-ui-title, default-create-in-idp-checkbox-unchecked, honor-cloud-provider-override-in-ui, idp-authenticated-embedding-endpoint, index-demo-videos-in-one-page.
- **Runs.** 63 succeeded, 0 failed. Judging cost $27.8991.

## Why each floor

### default-create-in-idp-checkbox-unchecked -- floor 80, low

The 75 row applies because this is an IAM/identity-provider write path -- the project's own README frames IAM groups as fine-grained access control and permission management -- and the failure mode is a silent authorization mismatch discovered long after the fact, not a visible break. The +5 applies because the task hinges on one specific thing, the API-contract default: management_routes.py:422 is documented as True (default), server_routes.py repeats that default on public and internal endpoints with CLI examples, registry_client.py already defaults False, and tests/unit/api/test_management_routes.py:698 pins the current default, so the flip must land consistently without silently changing documented CLI/import behaviour. Tier is low because it is a default changed across a couple of files -- state initialization, payload default, one route default, one new frontend test in the existing frontend/src/components/__tests__ suite and one inverted backend test -- with the opt-in IdP path already implemented and left intact.

### build-docker-images-from-uv-lock -- floor 75, medium

Floor row 70 because docker/Dockerfile.registry and docker/Dockerfile.auth feed build-registry.yml and build-auth-server.yml, which push multi-arch images to public.ecr.aws that users pull and run — it ships, and a defect reaches someone; it is not the 75 row because no authentication or authorization code path is edited, only the images' dependency install. The +5 applies because the task hinges on exact uv semantics rather than general care: uv sync prunes the venv and would wipe the intentional CPU-only torch/torchvision layer, installs the dev group unless --no-dev is passed, will not install the project itself given [tool.uv] package = false, and fails unless uv.lock joins pyproject.toml in the COPY. Medium tier because it spans several files and a CI surface — two Dockerfiles, four new lockfiles for auth_server and three servers/*, and a uv lock --check job over nine project roots — but adds no runtime logic or new subsystem.

### honor-cloud-provider-override-in-ui -- floor 70, low

Floor 70 because this is a production FastAPI route rendered in the operator-facing registry UI (UptimeDisplay.tsx), not an internal tool or docs page; it is not an auth, payment or data-deletion path, and the nginx_proxied_auth dependency is untouched, so 75 does not apply. Tier low because the production fix is a single awaited call swap in one file onto the already-correct _resolve_cloud() resolver, whose unset-override fall-through preserves backwards compatibility for free, with the remaining work being a two-case regression test in an existing test file that already has the auth-override and cache-reset patterns. No +5: the response shape, frontend types and precedence logic are all unchanged, so nothing hinges on authoring an API contract, version comparison or security invariant.

### fix-reserved-groups-var-in-service-account-script -- floor 80, low

Floor row 75 because verify_setup() is a security path: it is the only check that the M2M service account's group membership and groups protocol mapper — the authorization boundary for agent visibility — were provisioned correctly, and CLAUDE.md's standing security invariants explicitly cover any change touching auth/authorization and credential handling. +5 because the task hinges on one exact thing: replacing a substring grep with a real group-name comparison (the SC2128 latent bug, where mcp-servers-restricted matches mcp-servers-unrestricted) while handling bash's special GROUPS array under set -e. Tier low, not trivial, because it is more than one condition — a variable rename plus corrected array/exact-match semantics in verify_setup, repeated in setup-m2m-service-account.sh and cli/user_mgmt.sh after a sweep — but it adds no feature or config surface, so it falls short of medium.

### cli-custom-egress-oauth-provider-flags -- floor 80, low

Floor 75 because the change is the admin write path for egress OAuth credentials and outbound token/authorize endpoints, which CLAUDE.md's security invariants explicitly govern as auth/credential-handling and outbound-request territory; it does not sit lower even though the server re-validates every value and fails closed. Plus 5 because the task hinges on exact API-contract fidelity: five field names must match EgressConfigRequest verbatim, the client's None-sentinel 'only send what was supplied' convention must be preserved, and the token auth style flag must be constrained to exactly the TokenEndpointAuthStyle members post_body/basic_header. Tier low because it is two source files and a test module adding argparse flags and passthrough parameters against a pattern already present in the adjacent code, with no new endpoint, schema, or subsystem.

### derive-repo-url-from-skill-md -- floor 75, medium

Floor 70 because this is the shipped user-facing registry UI and a public parse-skill-md API response, not an internal tool and not a security or data-deletion path; +5 because the task hinges on one specific thing — exact inversion of the two SKILL.md URL shapes including the GitHub Enterprise raw-host convention already encoded in registry/utils/url_utils.py, with non-GitHub hosts left empty rather than guessed. Tier medium because it is two related features across roughly eight files (url_utils derivation, skill_service parse result, skill_routes response, Dashboard parse handler, SkillCard and SemanticSearchResults modals, Skill type and its mapping) with each edit small and patterned on existing code, rather than a new subsystem.

### consistent-csrf-across-toggle-endpoints -- floor 80, high

Floor 75: this is the CSRF/auth path itself (registry/auth/csrf.py plus the four toggle routes), which README documents as an Application Security hardening deliverable (#600) in a SOC 2/GDPR-audited, zero-trust posture, so a defect is a security regression rather than a visible bug. +5 because the whole change hinges on one specific invariant being exact -- the exemption predicate must key off absence of the session cookie, not a client-influenceable Authorization or nginx-injected X-Auth-Method header, or the fix becomes the bypass. Tier high: it rewrites a shared auth dependency's contract and applies it consistently across server, agent, skill and virtual-server routes (only three of four currently carry it), requires justifying a design among alternatives, and must be covered for both browser-cookie and bearer-token paths -- subsystem scope, like the skill's authenticated-endpoint and token-storage examples.

### configurable-ui-title -- floor 75, medium

Floor starts at 70 because this ships in a production service and the title is on surfaces users see including the pre-login page, and it modifies the Docker, Terraform/ECS and Helm deploy definitions rather than just frontend strings; it is not the 75 row because no auth, payment or data-deletion path is involved. The +5 applies because the task turns on one specific invariant -- 'deployments that do not set UI_TITLE must see no change' -- where an empty env var rendered by a compose file, task definition or Helm template must behave as unset, and because CLAUDE.md states the chart reservedEnvNames list and the extra_env_test index assertions are a matched pair that only helm unittest enforces. Tier is medium and not high: roughly twenty files, but each change is shallow plumbing of one optional setting through an existing settings object, the existing /api/config response and the existing System Config panel, with no new subsystem or endpoint.

### configurable-mcp-proxy-upstream-timeout -- floor 70, medium

Floor 70 because this is a shipped, user-facing request path in the auth-server, but not the auth/security row: the diff adds no authn/authz logic, only an upstream-timeout knob whose 30s default preserves existing behavior, with the connection-holding risk bounded by the enforced minimum. No +5 adjustment because nothing hinges on a single narrow invariant -- the settings field, MCP_PROXY_* env fallback, clamp, admin row and deployment wiring are all direct clones of the live mcp_proxy_max_body_bytes pattern, and the requested tests cover default/override/floor. Tier medium because it is a config surface threaded through ~14 files (config.py, server.py reader plus httpx call site, config_routes.py, three compose files, .env.example, Helm secret/values/reserved-env-names, five Terraform files, the unified parameter reference) -- more than a couple-of-file default change, far short of a new subsystem or authenticated endpoint.

### nginx-location-trailing-slash-route-hijack -- floor 80, medium

Floor 75 because the project's own agent map (CLAUDE.md:727-728) lists config generation alongside auth and authorization as the areas governed by its security-review rules, and the generated block at nginx_service.py:2262 is what enforces auth_request /validate, so a mistake misplaces an authorization boundary and stays hidden while a session cookie is present. +5 because the fix hinges on getting one exact thing right: nginx location-match semantics and precedence (prefix vs = vs ^~) while preserving the /name/mcp and /name/sse client contract -- a security invariant and an API contract decided by a single character of emitted config. Tier medium because it is a config surface touching the generator (nginx_service.py:2362-2368), the ^~ guards in the same template, the already-written-config migration path, and new tests -- several files around one bounded surface, not a new subsystem like rate limiting or an authenticated endpoint.

### registration-admission-control-gate -- floor 80, high

Floor 75 because this is a security/compliance enforcement path on the write side of the registry, which the codebase itself already treats as a blocking control (security_block_unsafe_servers/agents/skills, *_scan_on_registration in registry/core/config.py); +5 because correctness hinges on one specific invariant, fail-closed on timeout and unreachable gate, with no ungated path left, including POST /internal/register. Tier high because it is a new subsystem rather than an edit: config surface (enable flag, URL, timeout, gate auth), an outbound HTTP client with a request/response contract, wiring into 7 handlers across three large route files, distinct deny-versus-gate-failure errors surfaced to callers, logging, deployment wiring across .env.example, four compose files, Helm values and Terraform ECS, and four new test scenarios.

### server-side-oauth-token-storage -- floor 75, high

The 75 row applies because this is squarely a security path: OAuth access and refresh tokens encrypted at rest, a key-management choice, and a reference lookup that must be scoped to the authenticated user, in a repo whose own security-posture doc treats session encryption keys and the session cookie threat model as controls. No +5 adjustment: the risk is spread across schema, indexes, key derivation, callback wiring, endpoint authorization, TTL/revocation and the cookie-only-validation constraint rather than hinging on one contract or invariant. Tier is high because the skill's own high row names server-side token storage, and the change spans a new MongoDB collection with TTL and lookup indexes, the OAuth callback in auth_server/server.py, a new authenticated retrieval endpoint, backwards compatibility with the existing flow, and expired-and-revoked tests.

### lifecycle-workflow-webhooks -- floor 80, high

Floor 75 because this is squarely a security path: the signature exists to stop event forgery, and the new lifecycle permission is an authorization split enforced in four places including a batch processor that bypasses the HTTP handlers, matching the repo's own 'fine-grained authorization' and 'supply chain security' pillars in docs/security-posture.md. The +5 applies because the whole control hinges on one exact invariant — the HMAC must cover the exact transmitted bytes, and the current webhook_service.py posts via httpx json=payload, so a separately-serialized digest would mismatch with no runtime symptom. Tier high because it is a subsystem, not a feature: a signing scheme plus a new event plus a new permission plus a mandated-status config gate plus status= filters, replicated across servers, agents and skills, over 15+ existing webhook callsites and a LifecycleStatus model whose defaults already disagree between cards and registration requests.

### per-caller-per-target-rate-limits-and-quarantine -- floor 80, high

Floor 75 because quarantine is a security path by the repo's own framing: it is an absolute kill switch for a compromised caller, sitting inside an auth chokepoint the design doc marks as the critical path of every call and as a documented exception to the project's 'admission fails closed' principle. +5 because the feature hinges on one specific security invariant -- that a quarantine deny is unconditional, evaluated before any counter work, not subject to the existing admin bypass for a quarantined caller, and not swallowed by the RATE_LIMIT_FAIL_OPEN default when DocumentDB is unreachable. Tier high because it is a subsystem change spanning the models, limiter gate-building, both repositories, startup seeding, admin API delete-protection, the auth-server enforcement hook, the CLI and the React IAM surfaces, and it must resolve the composite-key delimiter hazard the design doc already flags for exactly this kind of extension.
